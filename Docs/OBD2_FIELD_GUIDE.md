# Полевая инструкция: сбор данных для профилей авто

Для команды. Цель: подключиться к машине тестовой сборкой, снять «паспорт» машины и добыть производительские данные для составления профиля. Время: 20–30 минут на машину.

**Понадобится:** iPhone с тестовой сборкой (вкладка **OBD Test**), адаптер (BLE, например OBDLink CX, или Wi-Fi ELM327), машина с заведённым двигателем (или включённым зажиганием).

**Безопасность:** все действия — на стоянке или с пассажирского места. За рулём в телефон не смотрим.

---

## Часть 0. Настройка экрана (1 минута)

1. Переключатель **BLE / Wi-Fi** — по типу адаптера. Для Wi-Fi сначала зайди в Настройки iOS → Wi-Fi → подключись к сети адаптера (имя вроде `WiFi_OBDII`/`V-LINK`; интернет на телефоне пропадёт — это нормально).
2. Переключатель авто: если тестируемая марка есть в списке — выбери её (тогда подключится и её профиль). Если нет — **«без авто»**: для сбора данных этого достаточно, работать будет стандартный слой. Чтобы проверить готовый профиль новой марки, попросите добавить её в селектор.

## Часть 1. «Паспорт машины» (5 минут, обязательно для каждой машины)

Строго в таком порядке:

1. **«ELM лог ▶» включить ДО Connect** — тогда в журнал попадёт инициализация и определение протокола.
2. **Connect** → дождись `Состояние: ready (протокол N, профили: …)`.
3. **Volt** — проверка связи.
4. **Live ▶** на 20–30 секунд → **Live ■**. В журнале появится сводка вида `live: стоп (obd2-standard: 38, toyota-tnga: 4)` — это главная строка отчёта.
5. **DTC**.
6. **VIN**.
7. Выдели весь нижний журнал пальцем → **Скопировать** → сохрани (заметки/мессенджер).

Если Connect завис на «поиск адаптера» — адаптер уснул: вынь/вставь его в разъём и повтори.

## Часть 2. Охота за производительскими данными (10–15 минут)

Команды вводятся в поле «команда…», отправка — кнопка **→**. Ответ приходит в журнал.

**Можно вводить (только чтение, безопасно):** `21XX`, `22XXXX`, `09XX`, `1902AF`, `ATSH…`, `ATCRA…`.
**НЕЛЬЗЯ вводить:** `04`, `14…` (стирание ошибок), `11…` (перезагрузка блока!), `2E…`/`2F…`/`3B…` (запись), `27…` (security access), `31…` (запуск процедур), `ATSP…`.

### Шаг 1 — двигатель

```
ATSH7E0
ATCRA7E8
22F190
```

- Ответ начинается с `62F190…` → блок говорит на UDS. Дальше пробуй DID из подсказок по марке (см. таблицу источников в `OBD2_PROFILE_COVERAGE.md`).
- Ответ `7F2211` → UDS-чтения нет (как у Toyota). Переходи к сервису 21:

```
2101
2102
2103
2104
2121
2182
21C4
```

- И проверь производительские DTC: `1902AF` (ответ `5902…` = поддерживается).

### Шаг 2 — коробка передач

```
ATSH7E1
ATCRA7E9
22F190
2101
2182
221E1C
221940
```

### Шаг 3 — другие блоки (по желанию)

То же для `7E2`/`7EA` (у гибридов там батарея), `7E3`/`7EB`.

**Как читать ответы:** `61…` или `62…` — данные, находка! `7F xx 11` — «сервис не поддерживаю», `7F xx 12` — «нет такой подфункции», `7F xx 31` — «нет такого идентификатора», `NO DATA` — блок молчит (возможно, его нет на этом адресе). Отрицательные ответы — тоже результат, их фиксируем.

## Часть 3. Калибровка находок (самое ценное)

Байты ответов расшифровываются сравнением дампов в разных состояниях машины с эталонными показаниями. Нужно **2–3 точки**:

- Точка 1: холодный запуск (утро, все температуры ≈ уличной) — самая информативная;
- Точка 2: прогретый холостой ход;
- Точка 3: сразу после поездки 15+ минут (или дамп в движении с пассажирского места — даёт скорость/нагрузку).

**На каждой точке, в этом порядке:**
1. **Live ▶ 10 секунд → Live ■** — это эталон (обороты, температуры, дроссель в этот момент);
2. ввести по очереди все команды-находки из Части 2;
3. скопировать журнал целиком.

Без Live перед дампами расшифровка почти невозможна — не пропускай.

## Часть 4. Что присылать

Одно сообщение на машину, по шаблону:

```
Машина: <марка, модель, год, двигатель, КПП, топливо>
Адаптер: <модель, BLE или Wi-Fi>
Улица: <температура>
Паспорт (Часть 1): [журнал]
Точка 1 (холодная): [журнал]
Точка 2 (прогретая, холостые): [журнал]
Точка 3 (после поездки / в движении): [журнал]
Наблюдения: <что удивило, что не сработало>
```

Дальше по этим данным составляется/обновляется JSON-профиль, в следующей сборке он приходит на проверку: в Live должны появиться строки `<профиль>/…`, а сводка показать `<профиль>: N > 0`. Значения сверяются с приборкой/логикой — и профиль получает статус «проверен» в `OBD2_PROFILE_COVERAGE.md`.

Кто хочет собирать JSON сам: формат — `OBD2_PROFILE_FORMAT.md`, процесс и статусы — `OBD2_PROFILE_COVERAGE.md`. Железное правило: профиль без живой проверки — «кандидат», в продакшен не идёт.

---

## Пример успешной охоты (Camry 2019, 08.07.2026)

Именно этим процессом за два выезда: выяснено, что Denso не поддерживает UDS-чтения (`7F 22 11`), найден рабочий сервис 21, блок `2101` размечен по 7 байтам сверкой с эталонным Live, а `2182` оказался температурой масла/АКПП с точностью 1/256° — данными, которых нет в стандарте. Итог — первый проверенный производительский профиль.

# Реестр профилей: статус покрытия и источники

Рабочий документ команды. Правило: **профиль без проверки на живой машине — «кандидат»**, в продакшен-подборку идут только проверенные. Проверка занимает минуты: экран OBD Test → выбрать авто → Connect → Live → сводка в логе покажет `<профиль>: N` (N > 0 = профиль отдаёт данные).

## Массовые источники (найдены командой, 08.07.2026)

- **[OBDb](https://github.com/OBDb)** (браузер: [obdb.community](https://obdb.community)) — community-база «один репозиторий = одна модель», сигналы в машиночитаемом JSON (`signalsets/v3/default.json`). Схема почти 1:1 наша: адреса ECU, команда, битовое смещение/длина, линейная формула. **Конвертер готов: `Tools/obdb_to_profile.py`** — после доработки 10.07.2026 (битовые флаги → `bitfield`, enum-карты → `enum`, `freq` = период опроса в секундах, вывод ответного адреса hdr+8) на Camry сконвертировал 296 из 299 сигналов автоматически (остались только не байт-выровненные поля шире 1 бита). Это главный источник массового наполнения; каждый результат конвертации — кандидат до живой проверки. **Доработка 13.07.2026:** конвертер разворачивает 29-битную адресацию OBDb-шортката `DAxx` (Honda, часть PSA) в ELM327-заголовки `18DA<ecu>F1`/`18DAF1<ecu>` и ставит профилю протокол 7; добавлены флаги сужения brand-репо `--only-hdr`, `--drop-path`, `--protocol`. Этим прогоном собраны 5 профилей: `toyota-prius-zw30`, `honda-civic-typer`, `honda-s2000`, `vw-transporter-t5`, `peugeot-407` (см. таблицу статусов — все 🟡 кандидаты, часть помечена «маловероятно»: brand-репо покрывают новые машины, а не целевые старые/иные версии).
- **[iternio/ev-obd-pids](https://github.com/iternio/ev-obd-pids)** — PID-база электричек от ABRP (папки по маркам: hkmc = Hyundai/Kia, ford, honda, mg…) — источник для EV-сегмента (SOC/SOH батареи).

## Toyota TNGA: разметка блока 2101 (живая калибровка, Camry 2019, 08.07.2026)

Ответ `21 01` → `61 01` + 27 байт. Смещения от начала данных (после эха `6101`).
Метод: три дампа в разных состояниях сверены с одновременными показаниями стандартных PID.

| Смещение | Значение | Формула | Сверено |
|---|---|---|---|
| 00 | Расчётная нагрузка | A×100/255 % | ✅ = std 0104 |
| 05, 06 | Температура впуска (2 сенсора?) | A−40 °C | ✅ = std 010F, падает при движении |
| 08 | Температура ОЖ | A−40 °C | ✅ = std 0105 |
| 09–0A | Обороты | AB/4 rpm | ✅ = std 010C |
| 0B | Скорость (кандидат) | A км/ч | ⏳ все дампы стояли (0) — проверить в движении |
| 0F | Дроссель | A×100/255 % | ✅ = std 0111 |
| 11 | Педаль газа D | A×100/255 % | ✅ = std 0149 |
| 12 | Педаль газа E | A×100/255 % | ✅ = std 014A |
| 13 | Актуатор дросселя | A×100/255 % | ✅ = std 014C |
| 18 | Напряжение (кандидат) | A/16 В | ⏳ похоже, не подтверждено |

`21 82` → `61 82` + 2 байта: **одна** температура `(AB/256) − 40 °C` (не две по A−40!). Датчик независим от ОЖ (после поездки 91° при ОЖ 87°) — масло ДВС или АКПП, различить по длинной поездке. **Разгадка из OBDb (Camry):** `2182` — температуры АКПП: поддон = байты 0–1 (формула совпадает с нашей 1:1), гидротрансформатор = байты 2–3 (на XV70 ответ был 2 байта — вероятно, отдаётся только поддон). `21 03` — топливный блок (тримы, дублирует std). `21 C4` — константы. `21 02` → NRC 12.

## Конвертация чужих форматов в наш

- **Torque-CSV** (Dr. Prius, Hybrid Assistant, PID-файлы форумов): автоматический конвертер — `Tools/torque2profile.py вход.csv выход.json --id … --prefix … --brands …`. Формулы переводятся численным зондированием в linear; составные/нелинейные пропускаются с отчётом — их переносим вручную.
- **OBDb** (github.com/OBDb, obdb.community): community-база по сотням моделей в едином JSON (`hdr`/`rax`/`cmd` + сигналы `bix/len/mul/div/add`, фильтры по годам) — структурно почти наш формат; главный источник для расширения покрытия. Конвертер готов: `Tools/obdb_to_profile.py` (на Camry — 296 из 299 сигналов автоматически: однобитовые сигналы идут в `bitfield`, enum-карты — в `enum`, `freq` трактуется как период опроса в секундах); вручную остаются только не байт-выровненные поля шире 1 бита (нужен bit-level extract в движке).
- **iternio/ev-obd-pids** (ABRP): PID батарей электричек (SoC/SoH) — источник для будущих EV-профилей.

## Процесс добавления профиля

1. Найти в источнике: адрес ECU (запрос/ответ), команду (`22`+DID или `21`+block), формулу, единицы.
2. Создать/дополнить `Classes/OBD/Profile/Resources/<группа>.json` (формат — `Docs/OBD2_PROFILE_FORMAT.md`).
3. Разметить самопроверку: параметрам-дублям стандартных PID добавить `crossCheck` (опора `std.*`), у остальных проверить `range` — по ним движок сам находит кривые раскладки.
4. Зарегистрировать файл в Xcode-проекте (Resources build phase).
5. Проверить на живой машине через экран OBD Test: после Live ■ в логе сводка + **отчёт самопроверки** (`аудит: …` — подозрительные значения и молчащие блоки). Кнопка **«Отчёт»** отправляет файл отчёта (JSON: конверт `LiveSessionReportEnvelope` — авто, VIN, версия сборки, протокол, полная статистика по каждому параметру) + текстовый лог сессии через системный share sheet — тестировщик скидывает их в чат, дальше по ним чистится профиль.
6. Обновить таблицу статусов выше: 🟡 → ✅ (или удалить параметр, если NRC/вне диапазона/расходится с опорой).

Неподошедший параметр не ломает ничего: ECU отвечает «не знаю» (`7F xx 31`), движок исключает его из опроса автоматически.
